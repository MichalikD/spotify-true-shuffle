# Contributing

Thank you for your interest in Spotify True Shuffle.

Contributions are welcome.

Whether you want to

- improve documentation
- fix bugs
- add shuffle modes
- improve performance
- review code

every contribution is appreciated.

---

# Philosophy

Spotify True Shuffle aims to remain

- modular
- maintainable
- predictable in structure
- intentionally randomized in output
- well documented

Please keep these principles in mind when contributing.

---

# Before You Start

Please read

- README.md
- docs/02_Architecture.md
- docs/08_Development.md

before making significant architectural changes.

---

# Reporting Bugs

When opening an issue include

- Spotify True Shuffle version
- Engine version
- Configuration version
- iOS version
- Scriptable version
- Debug output
- Steps to reproduce

The more information provided, the easier it becomes to reproduce the issue.

---

# Feature Requests

Feature requests are welcome.

Please explain

- the problem
- the proposed solution
- why it improves the project

Whenever possible discuss architectural changes before implementation.

---

# Pull Requests

Please keep Pull Requests focused.

Large changes should be split into multiple smaller PRs.

---

# Coding Guidelines

Please follow the Development Guide.

In particular

- preserve Engine Contracts
- preserve Output Contracts
- avoid duplicated logic
- update documentation
- keep modules independent

---

# Documentation

Documentation is considered part of the project.

Any significant feature should include documentation updates.

---

# Testing

Before submitting

verify

- Login
- Refresh Token
- Playlist Loader
- Shuffle Engine
- Playlist Writer
- Playback
- Settings

All existing shuffle modes should continue working.

---

# Code Style

Prefer

- readable code
- small functions
- descriptive names

Comment

why

instead of

what.

---

# Discussions

Architectural discussions are encouraged.

Spotify True Shuffle is intended to evolve as a long-term project.

Thank you for helping improve it.
